Multi-instance LLM data quality control

Problem

Finance business rules are written in natural language. Verifying them on large data volumes requires translating them one by one into checks, and a simple "error" report doesn't indicate where or why a data point is wrong.

Solution

I designed a system where multiple LLM instances, each assigned a batch of data, read the business rules and apply them to verify data acceptability.

When data is unacceptable, the system returns the exact columns and rows in error and the nature of the quality error. A report tracks error evolution, and Cloud Scheduler triggers execution automatically.

Key takeaway

An LLM verdict is only valuable if one can trace back to the rule and the data that produced it. This traceability question is what I want to explore in a PhD.

Multi-agent system with LangGraph

Problem

A complex task can be broken down into steps assigned to autonomous agents. The challenge is to make them collaborate in a controlled way, within a limited timeframe.

Solution

With my team, I implemented an autonomous agent solution using the LangGraph framework, which organizes agents as a graph and circulates information between them.

Key takeaway

In an agent chain, each agent takes the outputs of the previous one: an error can therefore propagate without any single agent bearing the full justification for the final decision. This is the starting point of the targeted PhD.

White blood cell classification with deep learning

Problem

Manual analysis of medical images is slow and varies between operators. The Kaggle dataset, over 10,000 images annotated by experts, is highly imbalanced: 60% neutrophils versus 2% basophils.

Solution

After a literature review, I used GoogleNet pretrained on ImageNet: frozen base layers, retrained top layers, new 5-class output. I compared this approach with MobileNet v2/v3, EfficientNet-B0, SqueezeNet, ShuffleNet v2, and ResNet18, using learning curves and confusion matrices.

Key takeaway

I learned to start from the literature, compare several models under the same conditions, and read a model's errors class by class rather than relying on a single overall score.

Customer churn prediction

Problem

A telecom operator wants to identify customers likely to leave in order to act in time. Churn cases are a minority, making accuracy alone misleading.

Solution

I prepared the IBM Telco dataset, trained and compared a Random Forest and XGBoost, tuned their hyperparameters, and evaluated using ROC-AUC and F1-score. I built a Streamlit app for demonstration.

Key takeaway

The choice of metric matters as much as the choice of model when classes are imbalanced.

Heart attack risk prediction

Problem

Early identification of at-risk patients helps caregivers decide. Records include age, sex, cholesterol, blood pressure, and heart rate, with missing values.

Solution

I cleaned the data, handled missing values, normalized variables, then compared logistic regression, Random Forest, and SVM using cross-validation, with accuracy, precision, recall, and F1-score. The project is organized with a preparation script, an exploration notebook, and tests.

Key takeaway

In healthcare, missing an at-risk patient costs more than a false alarm: recall therefore matters more than accuracy.
